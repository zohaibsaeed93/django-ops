01

Describe your Django application

Run the CLI in your Django application directory to create a non-secret configuration. Choose your module, hostname, and storage buckets.

djangoops init --help
djangoops compose
CLI · djangoops.yaml → Compose
02

Provision the runtime

For a VPS, install Docker and OpenSSH and provision the runtime environment and external S3 storage. For Kubernetes, register an existing namespace-scoped target.

djangoops deploy --help
djangoops backup-schedule --help
Your VPS or existing cluster
03

Connect the outbound agent

Provision the control plane's TLS certificate and runtime agent credentials. Configure the Go agent's trusted CA, endpoint, and project root. The dashboard-only development server does not start this gateway.

DJANGOOPS_CONTROLPLANE_ENDPOINT=ops.example.com:8443
DJANGOOPS_PROJECT_ROOT=/srv/djangoops/my-app
# Provision CA and agent credentials separately.
Agent → authenticated TLS gateway
04

Grant project access and verify

Create Project and AgentRegistration records through operator-controlled Django tooling, add your user to Project.members, then run a live diagnostic. Kubernetes control uses the typed GraphQL API.

POST /graphql/v1
# Session authentication + CSRF required.
djangoops health --help
Project-scoped dashboard + API
Read the repository runbooks for the complete provisioning steps: docs/phase1-agent-channel.md, docs/phase2-dashboard-graphql.md, and docs/phase3-kubernetes.md. The snippets above are orientation, not a complete production configuration.
